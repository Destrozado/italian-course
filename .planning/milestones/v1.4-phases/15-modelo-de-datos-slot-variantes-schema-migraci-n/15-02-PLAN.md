## Trust Boundaries

Web estática single-user, fully-local, sin servidor/red/auth. Inputs: el state en localStorage (editable a mano por el autor) y los ficheros de backup JSON que el propio autor importa.

| Boundary | Description |
|----------|-------------|
| localStorage raw → JSON.parse → migrate()/hydrate | Estado potencialmente corrupto o manualmente editado. |
| Fichero de backup → JSON.parse → parseBackupFile → cadena de migración | Import de un JSON arbitrario elegido por el autor. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-PP | Tampering | migrate5to6 / hydrateV6 / parseBackupFile sobre JSON con `__proto__` | mitigate | Deep-clone defensivo vía JSON.parse(JSON.stringify(...)) por sub-dict (CR-03 / T-04-02): reconstruye un root literal fresco, nunca asigna `__proto__` como prototipo. Test anti-prototype-pollution explícito (`({}).polluted === undefined`). |
| T-15-DOS | Denial of Service | migrate() con schemaVersion desconocido/corrupto | accept→mitigate | El dispatcher cae a warn + blankState() ante versión desconocida; nunca pierde el state del autor sin loguear. parseBackupFile rechaza con {ok:false, reason} en español ante shape inválida o versión más nueva. Riesgo de pérdida bajo (single-user, backup manual). |
| T-15-INT | Tampering | Pérdida de integridad del state al migrar | mitigate | Pureza + idempotencia (no muta input, re-ejecutar da shape idéntica) verificadas por test; cada sub-dict pasa por type-guard antes de clonar. |
</threat_model>
