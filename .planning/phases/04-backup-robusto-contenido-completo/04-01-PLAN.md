## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User filesystem → app | Usuario selecciona archivo .json arbitrario vía `<input type="file">`. El bytestream entra a `Blob.text()` → `JSON.parse` → `parseBackupFile`. App single-user desktop local. |
| localStorage → in-memory state | `loadState()` lee el blob `italianCourse.v1`. Si el blob fue editado a mano por el autor (acceso físico al navegador) la integridad shape se garantiza por `hydrateV3` defensivo. |
| App → user filesystem | `exportBackup` escribe Blob → anchor download. Salida controlada por el app; no escribe a paths arbitrarios (navegador maneja el download dialog). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | `parseBackupFile` (untrusted JSON import) | medium | mitigate | `JSON.parse` envuelto en try/catch que devuelve `{ok:false, reason:'JSON inválido: ...'}` (Pitfall #3). Type guards explícitos: `kind === 'italian-course-backup'`, `typeof state === 'object'`, `typeof state.schemaVersion === 'number'`. Reject schemaVersion>3. Reject wrapper.schemaVersion ≠ state.schemaVersion (Pitfall #6). Per D-74. |
| T-04-02 | Tampering | `JSON.parse` prototype pollution (`__proto__`/`constructor` keys) | low | mitigate | `hydrateV3` reconstruye el objeto con literal `{schemaVersion: 3, exerciseStats: ..., ...}` (Object.create equivalente — no Object.assign sobre prototipo). Cualquier `__proto__` en el JSON queda como property no-prototype tras la reconstrucción literal. Verificable con un test que pase `{"__proto__": {"polluted": true}}` y assertee `({}).polluted === undefined` después. |
| T-04-03 | DoS | FileReader sobre archivo gigante | low | accept | App single-user desktop local. Archivos JSON realistas ~50KB-500KB (state + 200 ejercicios). Si el autor accidentalmente selecciona un .iso/.mp4 renombrado a .json, el `JSON.parse` falla rápido con SyntaxError. No size guard explícito en v1 (Pitfall #3 cubre el crash). Si emerge en UAT, añadir guard `file.size > 5*1024*1024` como follow-up. |
| T-04-04 | Tampering | `state.lastBackupAt` futuro / clock skew | low | mitigate | `daysSinceISO` puede devolver negativo. `shouldShowBackupBanner` trata `days < 0` como "no mostrar banner" (Pitfall #5). `backupStatusLine` renderiza "(fecha futura)" sin crashear. Test cubre el caso. |
| T-04-05 | Information Disclosure | Export expone state plain JSON sin cifrar | low | accept | App single-user, archivo en disco del propio autor. No hay PII de terceros. | T-04-06 | Repudiation | `commitImport` reemplaza state sin trazabilidad | low | accept | Por diseño D-83/deferred — log persistente de imports descartado. El mensaje "Esto REEMPLAZARÁ tu progreso actual y no se puede deshacer" en el confirm dialog comunica la irreversibilidad. |
| T-04-07 | Tampering | Cascada D-54 cruzando state importado | low | mitigate | `commitImport` llama `resetSession()` ANTES de `this.state = ...` (Pitfall #10). El listener `@keydown.window` se desmonta automáticamente con el lifecycle del `<template x-if="currentScreen === 'session'">` (D-72). Test no requerido por simplicidad — defensa estructural. |
| T-04-SC | Tampering | npm/pip/cargo installs | n/a | mitigate | Phase 4 instala CERO paquetes externos. Stack 100% LOCKED (Alpine 3.15.12 + Pico 2.1.1 ya pinned con SRI en index.html desde Phase 1). Browser-native APIs (Blob, FileReader, URL, localStorage). `node:test` + `node:assert/strict` ya en uso desde Phase 1. NO Package Legitimacy Audit table needed (no installs). |
