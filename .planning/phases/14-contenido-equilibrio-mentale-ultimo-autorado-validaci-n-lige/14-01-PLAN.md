Shape de un documento de canción (content/songs/<slug>.json):
```json
{
  "id": "<slug ASCII ^[a-z0-9][a-z0-9-]*$, único>",
  "title": "<string no vacío>",
  "phrases": [
    {
      "id": "<string no vacío, único dentro de la canción>",
      "prompt": "<línea italiana, string no vacío>",
      "answer": ["<token", "español>", "..."],
      "distractors": ["<opcional; omitir o []>"],
      "categoryIds": ["<opcional; omitir o []; cada id ∈ las 9 categorías>"]
    }
  ]
}
```

Reglas que validateSongs (src/data/schema-validator.js) HACE CUMPLIR:
- id de canción: slug ASCII minúsculas, único entre archivos.
- title: string no vacío.
- phrases: array con AL MENOS 1 frase (phrases:[] se rechaza, WR-01).
- cada frase: id string no vacío + único dentro de la canción.
- prompt: string no vacío.
- answer: array de >=1 tokens, todos strings no vacíos.
- distractors: OPCIONAL. Si presente, array de strings no vacíos. (D-07: omitir por defecto.)
- categoryIds: OPCIONAL (LINK-03). Ausente o [] es VÁLIDO. Si presente, cada entrada string que referencia categoría conocida.

Las 9 categorías válidas para categoryIds (content/categories.json):
  avere, essere, preposiciones, verbos-movimiento, sustantivos-irregulares,
  genero-numero, profesiones, articoli, partitivos

Índice (content/songs.json):
```json
{ "songs": [ { "id": "<slug>", "title": "<string>", "phraseCount": <int == phrases.length> } ] }
```

loadSongs (src/data/content-loader.js): deriva los ids del índice songs.json, hace
fetch de content/songs/<id>.json, NFC-normaliza en el borde, valida con validateSongs.
La nueva canción aparece en el bloque Canciones SIN cableado adicional con solo añadirla al índice.
