<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| JSON de canción (disco) -> validador/loader | Contenido editado a mano; un typo o un blob malformado no debe romper el arranque silenciosamente |
| localStorage -> migración (state persistido) | El autor puede editar localStorage a mano o importar un backup; un sub-objeto malformado no debe contaminar el live state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01 | Tampering | localStorage state -> migrate4to5/hydrateV5 | mitigate | Deep-clone defensivo `JSON.parse(JSON.stringify(...))` por sub-dict (incl. songProgress) — neutraliza getters/`__proto__` como own-property (patrón CR-03 heredado de migrate3to4) |
| T-13-02 | Denial of Service | JSON de canción malformado | mitigate | validateSongs acumula errores y loadSongs lanza Error con `.errors`; el blob malformado no llega al runtime (banner visible, DATA-02) |
| T-13-03 | Information Disclosure | contenido de prompt/answer en el banner de error | accept | El banner usa `textContent` (main.js renderValidationBanner líneas 144-151) — el contenido del JSON se escapa, sin ejecución; sin PII en una app local single-user |

Nota: app LOCAL single-user, sin backend/red/secretos. No se modelan amenazas de servidor/auth/transporte.
</threat_model>
