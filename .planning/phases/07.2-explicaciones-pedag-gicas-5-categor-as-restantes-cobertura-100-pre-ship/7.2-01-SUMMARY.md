## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `Edit` del Batch A truncó cierre `},` + campo `notes` en 11 ejercicios (avere-002..012)**

- **Found during:** Task 1 sub-step 1d (verificación 1 — JSON parseable falla con `SyntaxError: Expected double-quoted property name in JSON at position 1284`).
- **Issue:** El primer Edit aplicado a avere-001 incluyó en su `old_string` el patrón completo `"correctIndex": N\n      },\n      "notes": "..."` y en su `new_string` reconstruyó todo incluyendo el cierre `},` del payload y el campo `notes` posterior. Pero los 11 Edits siguientes (avere-002..012) usaron un `old_string` demasiado corto (`"correctIndex": N\n      },\n      "notes": "..."`) y un `new_string` que omitió el cierre `},` del payload — el resultado fue 11 ejercicios con explanation pero SIN cierre del payload, dejando `}` huérfanos y rompiendo el JSON.
- **Fix:** Aplicados 11 Edits adicionales que añaden el cierre `},` + el campo `notes` con su valor original (extraído del HEAD pre-Batch-A via `git show HEAD:content/exercises/avere.json | python3 -c "..."`). El patrón final correcto: `"explanation": "..."\n    },` → `"explanation": "..."\n      },\n      "notes": "..."\n    },`.
- **Files modified:** `content/exercises/avere.json` (11 ejercicios reparados antes del commit del Batch A).
- **Verification:** JSON parseable exit 0; coverage 12/23; notes preservados verificados por comparación dictado vs HEAD original; D-88 invariante exit 0; git diff scope limitado a `+explanation + coma tras correctIndex` (cero cambio a notes en el diff final porque el reparo restauró el valor original).
- **Committed in:** `9a97616` (incluido dentro del commit del Batch A — el fix ocurrió pre-commit).

**Lección normativa capturada (replicable Plans 7.2-02..05):** cuando un ejercicio JSON tiene un campo posterior al payload (como `notes`), el `old_string` del Edit DEBE incluir el cierre `},` del payload + el campo posterior completo + su comilla de cierre. Usar ancla larga (mínimo 4-5 líneas) elimina ambigüedad y previene la truncación. Aplicar este patrón sistemáticamente desde el primer Edit del Plan 7.2-02.
