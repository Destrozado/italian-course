# Phase 28 — UI Design Contract: Responsive / mobile-friendly

> Visual and interaction contract for making ALL screens usable on a phone in portrait, **without changing the desktop appearance**. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This is a one-person, local, zero-build app on **Pico CSS classless 2.1.1** + Alpine.js 3.15.12. We do NOT introduce a new design system, new palette, or new framework. The contract is **CSS-first**: concrete breakpoints, the table→cards pattern, how each grid/header/button-row adapts, and touch targets. Markup changes are limited to minimal additions (e.g. `data-label` on `<td>`, a wrapping container). Everything responsive lives **behind media queries that only apply below the breakpoint** — desktop CSS is untouched.

## Breakpoints (Claude's Discretion → DECIDED)

CONTEXT.md left breakpoint count/value to the UI-SPEC. Decision: **one primary breakpoint**, mobile-first override applied only below it. Optional intermediate is a "razonable, no obsesivo" allowance (CONTEXT.md), not a hard requirement.

| Token | Value | Rule |
|-------|-------|------|
| `--bp-mobile` | **640px** | All responsive rules use `@media (max-width: 640px) { ... }`. Phone-portrait target. |
| (intermediate) | 641–1024px tablet | **No dedicated breakpoint required.** Pico's fluid container + flex-wrap on `.button-row` already handle this range gracefully. Add a narrow tweak only if a specific element overflows; do not build a full tablet layer. |

**Hard constraint (LOCKED, CONTEXT.md):** every new rule MUST be nested inside `@media (max-width: 640px)`. No edit to a selector outside a media query may change its desktop rendering. Desktop = anything ≥ 641px must render byte-identical to today.

**Container:** Pico classless already constrains `<main>`/`<body>` width with responsive horizontal padding. Do not add a fixed-width wrapper. On mobile the existing `<article>` cards already go full-width — keep that.

## Spacing Scale

Multiples of 4px. We reuse Pico's existing rhythm (`1rem` = 16px base) and the project's established values in `styles.css` (gaps of `0.5rem`/`1rem`/`1.5rem`). No new desktop spacing.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (0.25rem) | Inline gaps, badge-to-text, card label-to-value |
| sm | 8px (0.5rem) | `.wb-bank`/`.match-col`/`.wb-answer` gaps; card field vertical padding |
| md | 16px (1rem) | `.button-row` gap; default element spacing; card inner padding |
| lg | 24px (1.5rem) | `.button-row` vertical margin; section breaks |
| (touch) | **44px min** | **Mobile-only minimum touch target** for interactive controls (see Exceptions) |

**Exceptions:**
- **44px minimum touch height** for all tappable controls inside `@media (max-width: 640px)`: the "Examen" / "Jugar" buttons (today `secondary outline`, dense), word-buttons bank chips, match items, checkboxes' tap label, the `role="switch"` Contrarreloj toggle. Apply via `min-height: 44px` + adequate vertical padding on mobile only. Desktop keeps Pico's denser defaults. (WCAG 2.5.5 / Apple HIG 44pt.) This is the one place mobile spacing deliberately diverges from desktop.

## Typography

No font-size changes on desktop. On mobile we rely on Pico's responsive `:root` font scaling (Pico already reduces base font on small viewports). The only project-specific text-size rule that may need a mobile tweak is `.session-context` (currently `1.25rem`) and the timer.

| Role | Size | Weight | Line Height | Notes |
|------|------|--------|-------------|-------|
| Body / prompt | 16px (Pico `1rem`) | 400 | 1.5 (Pico default) | `<p x-text="...prompt">`. Do not shrink — readability of Italian/Spanish strings is primary. |
| Card field label (mobile) | ~13px (0.8em) | 600 | 1.4 | The `::before { content: attr(data-label) }` label in table→cards. Muted color, semibold so it reads as a label not data. |
| Card field value (mobile) | 16px (1rem) | 400 | 1.5 | The cell's own content. |
| Context heading | 20px mobile / 1.25rem desktop | 600 | 1.3 | `.session-context`. On mobile cap at ~`1.15rem` if it competes with the prompt; keep desktop `1.25rem` untouched. |
| Timer seconds | 16px | 700 | 1 | `.session-timer-secs`, `tabular-nums` (already set). Keep legible; do not shrink below 16px on mobile. |

Weights in use project-wide: **400 (regular)** and **600 (semibold)** — exactly two. No new weights.

## Responsive Component Contract (the heart of this phase)

Each item below is a behavior the executor must implement **inside `@media (max-width: 640px)` only**. Desktop rendering is the current code, untouched.

### 1. Home category table → vertical cards (LOCKED problem #1)

**Problem:** 6-column table (`index.html:166-208`) overflows on phone; the **"Examen" button (6th column, key action) falls off-screen**.

**Contract — table→cards via CSS, minimal markup:**
- Markup change (minimal, allowed): add `data-label="..."` to each `<td>` in the home table body so the card layout can render a field label. Labels in Spanish matching the headers: `Estado`, `Categoría`, `Racha`, `Ejercicios`, `Última vez`, `Examen`. (The "Categoría" cell may omit its label since the category name is the card title.)
- CSS pattern (mobile only): on the home `<table>`, set `thead { display: none; }`, `tr { display: block; }` (each row becomes a card with a bottom border / small margin), `td { display: flex; }` with a `td::before { content: attr(data-label); }` muted semibold label on the left and the value on the right (or label-above-value stacked — executor's choice, keep it scannable).
- The **"Examen" button must be fully visible and full-width-ish with a 44px touch target** inside its card row. Promote it from the dense `secondary outline` density to a comfortable tap target on mobile (still `secondary outline` color — no color change). Same for the Canciones list "Jugar" button (`index.html:256-259`), which is the same table pattern.
- The category-name card title should read as the heading of the card; the "fallada xN" `<small>` (`index.html:192-193`) stays attached to the Racha field.
- Apply the same table→cards treatment to BOTH tables: home categories (`index.html:168`) and Canciones list (`index.html:233`). They share structure; one media-query rule set covers both (scope by a class or by `figure table` within the relevant screens).

### 2. Button-row wrapping (LOCKED problem #2)

**Problem:** the 4-button row (Repaso 20 / Test completo / Canciones / Backup, `index.html:144-154`) does not wrap → **"Backup" falls off-screen**.

**Contract:**
- On mobile, `.button-row { flex-wrap: wrap; }` so buttons reflow to multiple rows. Each button keeps `flex: 1` but with a sensible `min-width` (e.g. wrap to two-per-row, or stack one-per-row on very narrow phones). Goal: all 4 buttons visible and tappable, none clipped.
- This single rule fixes every `.button-row` instance app-wide (home actions, picker select-all/clear, in-flight banner Reanudar/Descartar, word-buttons Comprobar/Siguiente, match Siguiente, session Reiniciar/Volver, backup export/import, confirm panel) — they all reuse `.button-row` (`styles.css:86-97`). Verify none looks broken when wrapped; the prominent variant (`.button-row-prominent`) should keep comfortable padding when stacked.
- Touch target: wrapped buttons get the 44px min-height on mobile.

### 3. Home Contrarreloj toggle

- The `.home-exam-timed` label + `role="switch"` (`index.html:161-164`) — note `.home-exam-timed` has **no CSS rule today** (confirmed: not in `styles.css`); it relies on Pico defaults. On mobile, ensure the switch + its "Contrarreloj ⏱" label sit on one comfortable tappable row above the table, with a 44px tap area. Do not let it crowd the button-row above it; preserve the existing vertical order (banners → button-row → toggle → table).

### 4. Picker

- Category checkboxes (`fieldset` of `<label>`, `index.html:293-303`): Pico already stacks `<label>` vertically. On mobile, ensure each checkbox row has a ≥44px tap height and comfortable spacing so fat-finger selection is reliable.
- "Contrarreloj" checkbox (`.picker-timed`, `index.html:308-311`) and the dynamic "Empezar" button (`index.html:314-317`): full-width comfortable tap targets on mobile. The `.picker-warning` text (`index.html:320`) wraps naturally — no change needed beyond it not overflowing.

### 5. Session header + response timer (attention area)

- `.session-context` (`index.html:347`) + progress `<header>` + `.session-timer` (`index.html:356-362`) must stack cleanly without breaking the header on a narrow screen.
- `.session-timer` is `display:flex` (bar `flex:1` + seconds, `styles.css:481-500`). On mobile keep the bar and seconds **on one row** (bar shrinks, seconds stay right-aligned with `min-width` already set). The bar must remain visible and not collapse to zero width — confirm `flex:1` holds at 320px. If the seconds label + bar are too tight at the narrowest width, allow the seconds to sit on a second line, but the bar must always be visible (CONTEXT.md: "debe verse y no romper la cabecera").
- Keep `tabular-nums` and the alert-red bar/seconds tone (already set, no color change).

### 6. Exercise types

**multiple-choice** (`index.html:371-424`): options live in a `.button-row` — covered by §2 wrapping. Each option button gets 44px touch height on mobile and wraps to its own line(s) for long option strings.

**word-buttons** (`index.html:439-500`, and `cancion` `index.html:654-698`):
- `.wb-bank` (`styles.css:182-187`) is already `flex-wrap: wrap; gap: 0.5rem` — flows on mobile by design. Confirm bank chips get a comfortable tap size (≥44px height) on mobile; `overflow-wrap: anywhere` already guards long tokens.
- `.wb-answer` (`styles.css:192-202`) already wraps. Keep `min-height: 3rem`; ensure placeholder text doesn't overflow at 320px.
- Comprobar/Siguiente `.button-row` — covered by §2.

**match** (`index.html:533-586`): **Claude's Discretion → DECIDED.**
- `.match-grid` is `grid-template-columns: 1fr 1fr` (`styles.css:260-265`). **Decision: keep 2 columns on mobile** (the left↔right pairing semantic is the whole point of match; stacking to one column destroys the visual relationship). Tighten the gap (`gap: 0.5rem` on mobile) and let each `.match-col` button shrink. `overflow-wrap: anywhere` on match items so long words wrap inside the narrow column instead of overflowing.
- Match items get ≥44px touch height on mobile.
- Keep the `.match-selected` outline, `.match-consumed` muted state, and `.match-flash` animation unchanged (color/animation untouched — WCAG single-flash preserved, `styles.css:296-309`).

### 7. Summary / cancion-summary / backup

- `summary` (`index.html:724-873`), `cancion-summary` (`index.html:897-940`): lists (`.summary-delta`, `.summary-errors`) are block-flow `<ul>`/`<li>` — they reflow naturally. Confirm the `.user-answer` red inline span and the `↔` match pairs wrap inside the `<li>` on narrow screens (`overflow-wrap: anywhere` already on `.user-answer`, `styles.css:413`). The final "Volver al home" / "Volver a Canciones" button gets a comfortable mobile tap target.
- `backup` (`index.html:965-989`): export/import `.button-row` — covered by §2 (wraps, full-width, 44px). Status line and message paragraph wrap naturally. Hidden file input unaffected.

### 8. Confirm panel (cross-screen)

- `.confirm-inline` (`styles.css:112-123`) is `position: fixed; top:1rem; right:1rem; max-width:22rem`. On a 320–360px phone, `max-width: 22rem` (352px) can exceed viewport width minus the 1rem right offset and clip. **Contract:** on mobile, allow it to span the viewport with side insets — e.g. `left: 1rem; right: 1rem; max-width: none;` (or `width: auto`) so the confirm/cancel buttons are never clipped. Its inner `.button-row` already wraps via §2.
