## Trust Boundaries

Esta es una web estática single-user, fully-local, sin servidor, sin red, sin auth. La superficie de amenaza real es estrecha: el único input es JSON editado a mano por el autor y cargado desde disco (`content/*.json`).

| Boundary | Description |
|----------|-------------|
| JSON de contenido en disco → JSON.parse → validateContent | Input "no confiable" solo en el sentido de poder estar malformado por error de edición humana. No hay actor malicioso remoto. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-VAL | Tampering | validateContent rama variantes | mitigate | El validator rechaza con banner visible toda shape malformada (variants[] vacío, superficie inválida, payload+variants, explanation ausente). Acumula errores sin throw (D-08). |
| T-15-XSS | Information Disclosure / XSS | Mensajes de error del validator (renderizados luego con x-text) | mitigate | Los mensajes de error son texto plano en español, sin HTML ni interpolación de payload crudo no escapado. El render del banner usa x-text (no x-html) — fuera de scope de esta fase pero el validator NO introduce HTML. |
| T-15-PP | Tampering | JSON.parse de contenido con `__proto__` | accept | El loader/validador de esta fase NO clona ni reconstruye objetos del contenido (solo los lee/indexa por referencia). La mitigación anti-prototype-pollution por deep-clone aplica al state en Plan 02 (migrate5to6/hydrateV6), no al contenido read-only de aquí. Riesgo bajo: contenido editado por el propio autor. |
